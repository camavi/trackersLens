# Standard LLM and Python Nodes

Purpose: reusable, fully inspectable LLM/Python nodes for manual UI and MCP authoring.
Read when: changing standard node discovery, configuration, execution or editor behavior.
Last updated: 2026-10-22.

## Ownership

`core/runtime/standard-node-templates.js` owns the shared declarative catalog: `llm-custom` (LLM Custom, AI Agents palette) and `python-custom` (Python Custom, Processors palette). These are built-in templates with exact `input`/`output` ports, not task-specific installed packages. Nodes retain ordinary runtime graph identities, configuration and links.

`core/desktop/standard-node-runtime.cjs` validates canonical settings and resolves the exact persisted node/workspace. It ignores caller-supplied executable source/configuration when running a standard node. Python source is the full persisted `config.code`; trusted managed pack requirements come from Core's existing catalog and are normalized to exact `==version` strings. `parametersJson` becomes `config.parameters`. There are no Python AI, filesystem, network or process grants.

Main reuses the existing sandbox broker, Electron JavaScript runner and Seatbelt Python runner. Internal `tl.standard.*` sandbox identities bind the source hash; they are not installed ZIP archives or records in `tl_packages`. Built-in execution does not require `TL_ENABLE_CUSTOM_NODE_SANDBOX`; installed package activation/execution retains that independent opt-in gate. Merely constructing the broker/runner does not execute code or install dependencies. Missing packs/isolation remain explicit errors, never an unsandboxed fallback or implicit pip install.

Core pack usage/removal also recognizes the persisted standard Python `packId`.

## LLM contract

Current transports reuse Core's loopback OpenAI-compatible/Ollama service and the very same native LM Studio adapter used by ordinary AI nodes and the explicit Codex Login bridge. `allowOnline:true` authorizes the Login path; API profiles remain loopback-only. The selected profile supplies endpoint/credentials. `core/runtime/ai-provider-catalog.js` owns the existing TL local definitions unchanged, shared by the renderer store and Core: saved IDs override defaults, reads create no profiles, explicit missing IDs fail, and Auto/local-first uses the shared local-online preference. Model discovery reads actual authenticated service catalogs. `lmStudioTransport` uses the native editor selector (auto/native/compatible); auto/native reuse `core/runtime/lm-studio-native.js` prepare/normalize rather than duplicating protocol code. With Streaming enabled, standard API nodes reuse the existing LLM observation factory in Core, preserving native SSE, compatible SSE and Ollama chat NDJSON, usage, terminal checks and durable observation segments. The same LLM Live inspector reads Core-owned observations and performs scoped status/stop through the existing standard-node boundary. Buffered settings remain supported; Login keeps its provider-events transport and is not labeled token streaming. Unsupported native message/response options fail explicitly and require selecting Compatible; no hidden retry. A placeholder model requires an actual catalog selection before generation. Optional node model overrides are explicit and traceable; API temperature, token limit, top P and JSON format reach the actual request. Blank numeric/model settings inherit the profile; maxTokens `0` omits a token cap. When a complete native node switches to Login, API-only parameters remain saved but are not forwarded; the runtime logs their dormant values explicitly. Codex-only reasoning/speed remain on Codex; Claude uses its existing separate Login bridge and can inherit the client model when blank.

The normal message uses `instructions` and an explicit `inputPath`, optionally encoded as JSON under `inputKey`. Blank inputPath selects the complete input. Advanced `messagesJson` can replace that message list using role/content or role/inputPath/format/key bindings. Provider messages never implicitly include the entire preserved local payload. `preserveInput` controls only the local output envelope; `outputKey` receives complete provider result, raw response, usage and provenance.

Optional `requireTruePath` and `guardTermsPath` are user-configured pre-call checks, including checks on advanced messages and instructions. They are not an automatic semantic/PII classifier. Failures and full producer evidence remain inspectable. The document acceptance uses known synthetic canaries, not a general privacy guarantee.

## UI and execution

`js/tl-standard-node-editor.js` uses `TrackerLensAiAgentEditor.open`, exactly the editor used by Knowledge AI runtime nodes: its native General tab, Provider/model tab and shared Input/Select/Textarea fields. The LLM composition hook preserves every native tab and provider control, appending only Custom-specific bindings/messages/checks/trace views. The full native contract is retained in agentContractJson; no native field is deleted by the Custom editor. The canvas Configure handler checks standard identity before generic Custom Node dispatch; inspecting only requestRuntimeNodeConfig would miss this entry-path regression. General presentation metadata is saved through existing runtime persistence; identity/workspace/ports stay fixed. Core model discovery is injected into the existing native model selector without sending profile secrets to the renderer. LLM tabs expose provider/model, full prompt/messages, input/output binding, explicit checks, complete configuration and data/logs. Python exposes full editable code, managed pack, parameters, complete configuration and data/logs. Model discovery is a named Core read using the selected profile, including private authentication. Auxiliary buttons have type=button; they must not submit the editor form. Controls retain values across tabs; save retains multiline text and trailing newlines. Unknown token usage is not rendered as fabricated zero counters; actual usage remains available in Data/Logs and outputs.

Canvas ports retain exact declared names rather than legacy AI Agent task/control aliases. Standard roots use ProcessorRuntime's sandbox dispatch; connected descendants use the same routing. The legacy AI Agent runtime excludes these nodes, preventing duplicate/fallback execution. A Flow with standard nodes remains page-owned because the persistence-only background worker has no sandbox execution bridge. MCP execution is Main-owned. This is not a new background-worker, general joins/cycles or Stop/cancellation guarantee.
